# AGENTS.md

## Правила разработки

### Память

- Запрещено использовать `malloc()` и динамическое выделение памяти.
- Запрещено использовать `new`, `delete`, `realloc`, `free` и любые другие функции динамического выделения.
- Для хранения данных используйте статические массивы, глобальные константы или объекты (stack/flash RAM, определённые до запуска).
- Нельзя создавать объекты неинтегральных типов внутри методов и функций. Все локальные переменные должны быть интегрального типа; составные данные — только в статическом или глобальном хранилище.

### Комментарии

- Комментарии в коде можно писать только по-русски.

### Параметры функций

- Большие составные объекты (структуры, классы, массивы) передавать только по указателю или ссылке.

### Статические методы

- Запрещено использовать статические методы в классах.
- Код, не зависящий от состояния объекта, писать как свободные функции вне класса.

### Состояние устройств

- Каждый класс, описывающий устройство, обязан иметь собственную структуру состояния (например, `RelayState` для `Relays`) и методы `getState()` / `setState()`.
- При добавлении нового класса, описывающего устройство, всегда добавлять структуру состояния вместе с методами `getState()` / `setState()`.
- Состояние устройства считывать и обновлять только через методы `getState()` / `setState()`. Прямой доступ к полям структуры состояния извне запрещён.
- Метод `setState()` должен не только обновлять внутреннее состояние, но и менять соответствующее состояние устройства (управляемую аппаратную часть). Для устройств с чисто входными ножками аппаратная часть отсутствует — это описывается в комментарии метода.
- При сравнении двух состояний запрещено читать их внутренние поля извне: для структуры состояния определить оператор `==` и сравнивать состояния через него.

### Стейт-машины

- Для стейт-машин используется библиотека TinyFSM (подключена в `lib_deps`).
- События и базовый класс машины объявляются в общем заголовке машины в подпапке `statemachine` пакета устройства (например, `src/device/statemachine/device_state_machine.h`); общая таблица переходов — в парном файле реализации.
- Каждое состояние — отдельный класс в отдельной паре файлов «заголовок + реализация» в этой же подпапке: одно состояние — один файл (например, `charging_off_state.h` / `charging_off_state.cpp`). Не объединять несколько состояний в одном файле.
- Логика переходов и действия состояния описываются в его собственном классе (методы `react` / `entry` / `exit`); новые состояния добавляются без изменения существующих.
- Вызовы статических методов TinyFSM (`start`, `dispatch`) оборачивать в свободные функции (правило «Статические методы»).
